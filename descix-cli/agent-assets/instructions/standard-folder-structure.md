# Standard DeSciX Workspace Structure (Mono-Repo)

This document defines the canonical folder structure for DeSciX workspaces. Following this structure ensures consistency, discoverability, and seamless integration with platform tools.

## Workspace Hierarchy

DeSciX uses a "Mono-Repo" style structure where multiple communities and apps can coexist in a single workspace.

```
/ (Workspace Root)
├── .descix/
│   ├── workspace.json          # Workspace configuration (maps communities/apps)
│   └── wallet.json             # Developer credentials (DO NOT COMMIT)
│
├── [Community_ID]/             # Community Folder
│   ├── community_assets/
│   │   ├── icon.png
│   │   └── description.md
│   │
│   └── [App_ID]/               # App Folder
│       ├── assets/             # App Metadata
│       │   ├── app_description.md
│       │   ├── icon.png
│       │   └── system_instructions.md (AI Persona)
│       │
│       ├── kb/                 # Knowledge Base (RAG)
│       │   ├── staging/        # Local files to push to Drive
│       │   │   └── new-doc.pdf
│       │   ├── General/        # Converted markdown (from Drive pull)
│       │   │   └── *.md
│       │   └── chunks/         # JSON chunk files (for vectorization)
│       │       └── *.chunks.json
│       │
│       ├── site/               # Frontend UI (Optional)
│       │   ├── index.html
│       │   └── src/
│       │
│       └── microservice/       # Backend Logic (Optional)
│           ├── Dockerfile
│           ├── package.json
│           └── src/
```

## Folder Purposes

### Root Level
- **`.descix/workspace.json`**: The source of truth for which apps are active in this workspace. Generated by the PWA Setup Flow.
- **`.descix/wallet.json`**: Your authentication credentials.

### Community Level (`[Community_ID]/`)
Contains all apps belonging to a specific community.
- **`community_assets/`**: Metadata for the community itself (branding, description).

### App Level (`[Community_ID]/[App_ID]/`)
Self-contained folder for a single application.

#### `assets/` - App Identity
- **`app_description.md`**: Public description for the App Store.
- **`system_instructions.md`**: Instructions for the AI Agent that interacts with users of this app.
- **`icon.png`**: App Icon.

#### `kb/` - Knowledge Base
The KB folder supports both local-first (Git mode) and Drive-based workflows:
- **`staging/`**: Place raw files here (PDFs, images) to push them to Drive via `descix kb push`.
- **`General/`**: The canonical source of text content. Files here are pulled from Drive and converted to Markdown via `descix kb pull`.
- **`chunks/`**: Processed JSON chunk files ready for vectorization via `descix kb sync`.

**CLI-Centric Processing (Git Mode):**
```bash
descix kb push   # Push staging/ -> Drive
descix kb pull   # Pull Drive -> General/ (converted to markdown)
descix kb chunk  # Generate chunks from General/ -> chunks/
descix kb sync   # Push chunks to Pinecone via service layer
descix kb build  # Convenience: pull → chunk → sync
```

#### `site/` - Frontend
- Contains the static website or Single Page Application (SPA).
- **`index.html`**: Entry point.

#### `microservice/` - Backend
- Contains the server-side logic.
- **`Dockerfile`**: Defines the runtime environment.
- **`src/`**: Source code.

## Configuration Files

### `.descix/workspace.json` (Root)
```json
{
  "version": "2.0",
  "communities": {
    "my-dao": {
      "apps": {
        "governance": { 
          "localPath": "my-dao/governance",
          "sync_mode": "git"
        },
        "treasury": { 
          "localPath": "my-dao/treasury",
          "sync_mode": "drive"
        }
      }
    }
  }
}
```

**`sync_mode` Options:**
| Mode | KB Source | Use Case |
|------|-----------|----------|
| `git` | Local files | CLI-managed apps, developers (default for CLI) |
| `drive` | Pull from Drive | PWA-created apps, non-technical users |

**Note:** The CLI only supports `git` mode operations. If you are using the CLI, you are effectively in `git` mode.

## Agent Workflow for Migration

When encountering an unstructured project:

1.  **Analyze**: Identify which files belong to Frontend (`site`), Backend (`microservice`), or Documentation (`kb`).
2.  **Scaffold**: Create the standard folder structure if missing.
3.  **Move**: Relocate files into their respective folders.
4.  **Refactor**: Update relative import paths in the code to reflect the new locations.
5.  **Update Config**: Ensure `workspace.json` has the correct app mappings.
